Normal-user map feature module.

The route entry is UserMapView.vue: the shared UserMapShell plus a right-hand
icon strip (UserMapRightSideBar) carrying the one tool a normal user gets,
Smart Analysis.

Smart Analysis flow: click the strip icon -> draw a polygon on the map ->
Analyze Area -> pick one of four analyses -> fill its form -> read the results.
The drawer keeps the map on screen the whole time.

All four options end in their own wide landscape report modal with Close / Save /
Export PDF. The drawer only carries the option list and the forms.

The suppliers and spaces reports can jump the map to a location: the modal emits
`focus`, UserMapView dismisses the report and calls focusLocation on the canvas.

  UserMapView.vue         route entry. Shell + strip + tool wiring only.
  components/             strip, drawing HUD, drawer, option list, four forms.
                          The four report modals and their action bar live in
                          src/components/smart-analysis/.
  composables/            useAreaDrawing (polygon capture), useSmartAnalysis
                          (flow). useSavedReports and useAnalysisReportExport
                          live in src/composables/.
  constants.ts            category / business type / scale / days / hours / size sets.
  utils/                  geo (centroid + haversine, shared),
                          suitabilityReport (option 1),
                          topBusinessesReport + businessCatalog (option 2),
                          nearestSuppliersReport + supplierDirectory (option 3),
                          nearestSpacesReport + spaceInventory (option 4).
                          Flow/result/report shapes live in src/types/smart-analysis.types.ts.

ALL ANALYSIS RESULTS ARE STATIC. The util files derive figures from the form
input with a seeded hash so a selection always renders the same numbers;
businessCatalog.ts, supplierDirectory.ts and spaceInventory.ts are authored
reference data for Butuan City. The one real computation is distance, a haversine
from the drawn polygon's centroid to each record's coordinates. There is no
scoring model, no spatial query and no backend call yet — swap those files out
when the real engine lands.

spaceInventory.ts's first three buildings mirror RENTAL_SPACES in
@/services/chatbot/chatbot.static-data so the map and the chatbot never disagree
on the same property. Edit the chatbot record, not the copy.

Saved reports go to localStorage, not a table: there is no suitability_reports
schema yet.

Do not import from (admin)/, (space-owner)/ or (entrepreneur)/ here. Shared map
pieces live in src/components/map/ and src/stores/admin.map.store.ts.
